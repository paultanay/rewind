# RW006 — Node Pressure → Pod Eviction

**Status:** Implemented (Phase 4)
**Confidence potential:** High

## Pattern

A `NodePressure` event on a Node entity, followed within 5 minutes by
`PodKilled` (eviction) events on pods scheduled on that node, followed by
service-level metric degradation.

## Rationale

Kubernetes evicts pods from nodes under memory or disk pressure using the
eviction manager. Evictions cause a service disruption window while the pod
reschedules (typically 10–60 seconds, longer with image pull). This rule
connects the node-level event to service-level impact.

## Node condition types

- `MemoryPressure` — most common; triggers when available memory < eviction threshold
- `DiskPressure` — triggers on ephemeral storage exhaustion
- `PIDPressure` — process ID table exhaustion (rare)

## Interaction with other rules

- RW009 (crash loop) may fire if the evicted pod fails to restart cleanly
- RW003 (OOMKill) may co-fire if the node pressure was caused by a leaking pod

## Example

`
14:23:00  NodePressure  worker-2  MemoryPressure=True (avail: 142Mi/8Gi)
14:24:00  PodKilled     checkout-7d9f-abc  (evicted, node: worker-2)
14:24:00  PodKilled     frontend-5bc-xyz   (evicted, node: worker-2)
14:25:00  Anomaly       error.rate ↑ (checkout, frontend)
`

Result: RW006 fires with HIGH confidence; worker-2 named as trigger.
