# RW005 — Upstream Service Cascade

**Status:** Implemented (Phase 4)
**Confidence potential:** Medium

## Pattern

`error.rate` change-point ↑ on service B (upstream), followed within
15 minutes by `error.rate` change-point ↑ on service A (downstream), where
the topology graph has a call path from A → B.

## Rationale

In synchronous microservice architectures, a failure in an upstream service
propagates downstream within seconds to minutes as requests fail, timeouts
accumulate, and circuit breakers trip. This rule detects that fan-out pattern.

**Direction convention:** "upstream" is the service that is *called*. If
`checkout` calls `payments`, then `payments` is upstream of `checkout`.
The topology graph edge is `checkout → payments`.

## Topology source

Call-graph edges come from Grafana Tempo trace analysis (service-to-service
call frequency) or from static topology configuration in `rewind.yaml`.
Without topology data, RW005 cannot fire.

## Scoring

| Upstream → Downstream gap | Base score |
|---|---|
| 0–2 minutes | 0.60 |
| 2–5 minutes | 0.45 |
| 5–15 minutes | 0.25 |

Bonus: +0.10 if the magnitude ratio (upstream / downstream) > 2× (suggesting
the upstream is the primary failure, not just a symptom).

## Example

`
14:05:00  Anomaly  payments   error.rate ↑41×   (upstream)
14:07:00  Anomaly  checkout   error.rate ↑19×   (downstream, calls payments)
`

Topology edge: checkout → payments. Gap: 2m.
Result: RW005 fires with MEDIUM confidence; payments named as trigger.
